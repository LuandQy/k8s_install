# Web 表单与配置工作台

本说明适用 **20261115-r6**。本版为三步极简向导：填写配置、校验与计划、执行与台账。默认启动为配置模式；管理员显式启用独立执行器后，第 3 步直接提交后台安装，不弹二次确认，见 [Web 一键部署](web-deployment.md)。reset、redeploy、扩容与人工分步维护仍通过 CLI。 快速选择默认值和连接方式见 [快速上手](quick-start.md)。

实际部署可选择 CLI，或连接管理员执行器的 Web 三步向导。本文说明两种模式共有的配置功能：页面直接编辑当前配置，使用 .env 导入/导出持久化，不接管已有回执。密码只保留在当前页面内存；不得把配置副本当作“空白新环境”绕过旧集群维护。

## 启动与停止

需要 Linux、Python 3.8+、Bash 和 jq；已验证的运行组合为 Python 3.12/Linux，其他组合仍需接收方确认。使用 Python 标准库和本地静态资源，不需要 Node、npm、CDN 或下载依赖。脚本拒绝以 root 启动；不要使用 sudo。

从已校验的新解包项目目录启动，指定项目外独立草稿目录，父目录须已存在：

```bash
bash deploy.sh web --data-dir /tmp/rise-config-drafts --port 8765
```

也可使用 `--port 0` 自动选择空闲端口。服务固定绑定 `127.0.0.1`，没有 `--host` 或远程监听参数。终端输出带 `#token=...` 的临时访问链接，在运行服务的同一台电脑上用浏览器打开；不得转发该链接。页面读取令牌后移除地址栏中的片段，令牌仅保留在该标签页的 sessionStorage；关闭会话或服务重启后使用新启动链接。不要把链接、配置或浏览器会话截图作为公共交付附件。

按 Ctrl+C 停止服务；已保存草稿保留。再次使用同一目录启动后可打开草稿。`/tmp` 可能被系统清理，需要长期保留时改用自己受控的项目外目录并单独备份。草稿是敏感的节点/路径配置资料，不能加入对外发行包。

目录必须是新目录、当前用户所有且权限 0700 的空目录，或由本工作台建立的专用草稿目录。服务拒绝接管非空未知目录、项目目录及其父/子目录、符号链接目录；不会调整既有目录权限来绕过保护。数据文件为 0600，草稿 ID 由服务生成，单目录只允许一个服务进程持锁。

## 操作流程

1. **新建或打开草稿。** 初始地址使用文档示例网段，必须按实际目标环境修改。草稿名称仅用于本机管理，与 CLUSTER_NAME 分开。默认示例为一个同时包含 control_plane、worker、registry 角色的节点，数据策略 native；集群名称默认 rise。Web 不检查现场重名，也不自动识别本机或远端系统。
2. **填写表单。** 配置字段按基础部署参数与高级/安全选项分层：基础项首屏展开，包括集群标识、依赖模式、离线归档路径与 SHA256、K8s 版本、NTP/NFS、Harbor 启用和连接认证；高级项默认折叠，包含固定 known_hosts、自带根 CA、Pod/Service CIDR、镜像源覆写、底层路径/超时等。修改任一高级项后标题旁显示“已修改自定义项”。每个节点有 13 个字段，最多 32 个节点。节点字段按连接方式、认证方式、数据策略做声明式显隐；隐藏控件自动 disabled，不参与提交。节点角色可多选；路径/设备/证书字段只表示配置值，不进行磁盘选择、私钥读取或节点操作。

   节点以紧凑矩阵展示：主机名、连接/内网 IP、连接方式、SSH 用户/端口、SSH 密码、角色和“克隆行/删除”；“更多节点参数”折叠 OS/架构/数据策略等。每行数据盘路径下有实时预览：`native` 只声明数据根目录，不创建组件软链接、不格式化/分区；`existing/auto/format` 才显示 CLI 的 `/var/lib/*` 链接布局。启用本地存储或 NFS 时仍会创建 `LOCAL_PATH`/`NFS_PATH`（默认 `/data/local-pv`、`/data/nfs`）。可在“表单编辑 / env 预览”中查看服务端生成的 env。矩阵内“克隆行”复制连接端口、用户、认证、草稿密码和角色，并递增名称末尾数字与 IPv4 末位。节点 SSH 密码在矩阵行内；Harbor 管理员密码也只在该行勾选 Harbor 角色且为受管单机/HA 时显示，所有 Harbor 行共享同一个页面值。页面不保存密码，刷新后需重填；密码不进入配置对象或默认 env 导出。sudo 仍要求预先配置免密，CLI/Web 不采集 sudo 密码。Harbor 密码格式仍由 CLI 校验（12–128 位）。
3. **保存草稿。** 允许保存尚未完成或跨字段冲突的草稿；保存不等于参数通过。草稿采用修订号，两个页面同时修改时，旧修订返回冲突，保留当前编辑，不强行覆盖。可先导出本地修改，再打开最新版本核对。保存请求超时必须先刷新列表核对，不盲目重复提交。
4. **校验配置。** 受控适配层生成临时 env，调用现有 `deploy.sh config-check --json`，复用 `load_env/validate_env` 的最终组合规则；不另写一套网络/角色/版本规则。失败只显示适用于配置校验的诊断，不显示部署恢复提示。
5. **查看只读计划。** 调用同一 `deploy.sh plan --json`，显示实际 workflow 推导的阶段、已知阻塞和未核验项目。修改表单会使旧结果失效；请求期间的旧结果也不会覆盖新表单。结果同时展示当前 SSH 策略：控制端到节点，不是节点两两免密，私钥不分发；Web 没有检查密钥存在性、匹配、授权冲突、SSH 登录或 sudo 免密。
6. **导出 env。** 下载安全字面量配置供管理员另行复核；导出本身不授权安装。不要覆盖旧集群绑定的 env、state、runs 或 PKI。Web 草稿会明文保存 Harbor/节点密码，这是本版简化向导的明确取舍；配置对象和默认 env 导出仍不含密码。指定显式导出选项时才把凭据写入 env 文本，该文件必须按凭据材料保管。

`valid=true`、HTTP 200、计划生成成功或空 blockers 都不表示目标环境已经可部署。输出继续明确 `execution_authorized=false`、`live_checks_performed=false`。计划不会校验现场身份、磁盘、内存、部署回执、实时健康或持续 I/O；历史阶段成功也不是当前健康。

## 导出后交给 CLI

草稿保存位于服务专用目录，**不会写入项目的 cluster-vars.env**。点击“导出 env”后，将下载文件保存在受控位置并审阅内容，不覆盖旧集群文件。每个新终端显式设置实际文件路径；例如接收方已经将文件保存为 `/srv/rise-config/site-new.env`：

```bash
set -e
CONFIG=/srv/rise-config/site-new.env
test -f "$CONFIG"
test -r "$CONFIG"
chmod 600 "$CONFIG"
bash deploy.sh config-check --env "$CONFIG" --json
bash deploy.sh plan --env "$CONFIG" --json
```

这里只对自己保管的新导出文件设置 0600。配置由 root 保管时，由获授权管理员以相应身份进行只读检查，不能用 sudo 启动 Web 或放宽旧配置权限。默认 CLI 向导文件的路径及两类读取身份完整示例见 [配置到 CLI 的衔接](configuration-workflow.md)。

新环境实际部署前还须满足前置条件，由管理员显式传入同一路径：`sudo bash deploy.sh --env "$CONFIG"`，在菜单选择“安装 → 使用已有配置范围 → 复用”，审阅后确认。`--env` 不复制或上传配置；修改 Web 草稿不会同步现场文件。已有集群仍按 [维护手册](operations.md) 使用原回执和匹配代码。

## 归档 SHA256 与只读执行器接口

Web 表单不再提供手动 SHA256 输入或计算按钮。后端在保存、校验、计划和执行预览时，
按 `ARTIFACT_FILE` 自动读取同目录 `.sha256`，否则读取 `artifact/SHA256SUMS`；
实际部署仍由 CLI 校验归档字节。外部自定义路径可继续使用 CLI 摘要命令：

```bash
./deploy.sh artifact-sha256 --file /absolute/archive.tgz
```

它由可信本机管理员执行，不读取配置、不连接节点，也不把路径或摘要写入草稿。

## 包内路径建议与 SSH 选择

首屏“填入包内离线归档路径”使用服务提供的固定 `artifact/kubekey-artifact.tgz` 建议。服务只检查该固定路径的安全性和文件类型，不扫描其它目录，不读取归档内容或计算摘要。候选不存在、为链接或路径不符合 ASCII 规则时，按钮禁用并显示原因，不填入假值。

点击后仅把当前草稿的 ARTIFACT_FILE 改为该路径、ARTIFACT_SHA256 清空、DEPS_MODE 改为 iso，保留其它字段。它不会自动保存，也不会覆盖其它草稿；当前校验/计划立即失效。先独立核对 `artifact/SHA256SUMS` 与内层 tgz 摘要，再填写 ARTIFACT_SHA256。手工路径仍可编辑，不能将外层交付包误填为内层制品。

模型保留既有默认值：CLUSTER_NAME=rise、DEPS_MODE=iso；快捷按钮的 iso 变更是用户显式选择，不是导入或打开旧草稿时自动迁移。local 指未来运行部署 CLI 的控制端本机，最多一个；ssh 使用远端地址和认证方式。bootstrap 表示以后配置控制端到节点免密，key 表示复用已有密钥，password 表示持续密码登录；SSH 免密不代替普通用户的 sudo -n 权限。实际密钥及授权文件检查由正式 CLI 接入阶段执行；Web 部署任务调用同一流程，准备计划不能代替接入验收。

## 受限 env 导入

可选择本地文件或粘贴文本。浏览器限制为 **128 KiB**；服务限制整个 JSON 请求为 **256 KiB**。导入只解析数据，不通过 Bash、eval 或 exec 解释上传文本。成功后载入一个新的未保存草稿，不覆盖当前已保存草稿；失败保持当前表单。

支持：

- 已知大写字段的 `KEY=字面量`，每行一个赋值及可选注释、空行；CRLF 转为 LF。
- 单引号、受限双引号、转义裸值、拼接字面量；兼容模板的多行单引号 NODES 和向导 `%q` 产生的节点表示。
- ANSI-C `$'...'` 仅支持 `\n`、`\t`、`\r`、反斜杠及引号转义；最终值仍受类型与字符限制。
- 显式 NODES，每个非空行恰有 13 列；缺省的已知配置项按统一模型默认值补齐。空 NODES 可以保存为未完成草稿。

拒绝：未知字段、重复赋值、export/source/函数/命令、变量展开、命令替换、算术、数组、重定向、here-document、续行，以及密码值变量和运行控制参数。`HARBOR_PASSWORD`、`NODE1_PASSWORD` 等值不得导入；节点的 `password_env` 仅保留变量名称。`SSH_KEY` / `HARBOR_KEY` 可填写路径，不接受私钥正文，也不读取这些字段指向的文件。

这不是完整 Bash 解析器。包含自定义逻辑、重复覆盖变量、空数字/布尔或非受限语法的旧 env 应在独立副本中人工整理，不能要求工具执行脚本以“兼容导入”。模型提供完整受支持字段，不从现有公开 JSON 子集逆推或丢弃未识别字段。

## 本地读写与访问边界

- 所有 API 需要每次启动生成的随机令牌；校验 Host，变更请求还要求同源 Origin；不启用 CORS。静态资源采用固定映射，不提供任意文件浏览，页面采用 CSP 与文本渲染防止输入成为 HTML。
- HTTP 服务是单机普通用户工具，使用标准库，不是面向公网或多用户的生产服务。不要对外代理、开放监听或共享会话；本版执行权限通过独立 root 执行器、指定 UID 与本机 socket 显式启用；远程、多用户场景不在支持范围。
- 配置服务的只读子进程入口固定为 config-check/plan，参数独立传递，环境重新构造，不继承 BASH_ENV、CLI 覆盖、密码或任意用户环境。并发校验最多 2 个，每个 15 秒超时；超时停止该只读进程组。
- 生成的临时 env 位于私有临时目录，0600，正常完成/校验失败/超时后清理。配置服务只持久写入专用草稿目录，不接管已有 state/runs；可选执行器另在管理员指定的专用目录保存任务，并由 CLI 产生正常部署回执。
- 任务日志**不做脱敏**（本副本的明确取舍）：只清理终端转义、限制单行与总量。日志可能包含密码、私钥路径和完整命令，页面默认按 Info 过滤显示，Debug 模式显示全部；日志与任务目录按凭据材料保管。
- **只读不等于完全不访问本地文件。** plan 会检查 ARTIFACT_FILE 是否存在；同时指定 SSH_KNOWN_HOSTS 和 SSH_KNOWN_HOSTS_SHA256 时，共享校验会读取并核对该公钥文件摘要，Web 限定为不超过 1 MiB 的非符号链接普通文件。只填写已审阅的公钥文件，不用该字段指向凭据。不会连接节点或校验归档内容。
- 草稿最多 200 个，无删除 API。需要归档时先停止服务，在受控位置备份目录；不要手改修订号、工作流或标志文件绕过校验。

## 配置 HTTP 契约

仅本地使用，模型 `schema_version=1`；`config` 包含 `settings` 与 `nodes`，字段元数据来自 `web/schema.json`。

| 方法 / 路径 | 用途 |
| --- | --- |
| GET /api/schema | 字段元数据、示例配置及固定包内归档建议 |
| GET /api/drafts | 草稿名称、ID、修订号、更新时间；不返回完整配置 |
| GET /api/drafts/{id} | 读取指定草稿 |
| POST /api/drafts | `{name, config}` 新建草稿 |
| PUT /api/drafts/{id} | `{name, revision, config}` 保存；旧修订 409 |
| POST /api/import | `{text}` 受限解析为配置 |
| POST /api/export | `{config}` 或 `{config, credentials, include_credentials}` 返回 env 文本与下载文件名；密码仅在显式 `include_credentials=true` 时写入 |
| POST /api/validate | `{config}` 参数校验 |
| POST /api/plan | `{config}` 静态计划 |
| POST /api/execution/artifact-sha256 | `{path}` 仅执行器就绪时；返回 `{sha256,bytes,path}`，路径限制在执行器发布目录内 |

`GET /api/schema` 返回 `{schema, default_config, suggestions}`。`suggestions.artifact_file` 为 `{value: string|null, reason: string}`；不可用时 value 为 null，reason 供界面解释。它不是任意路径查询接口。字段中的 `option_labels` 和 `option_help` 以原始枚举值的字符串为键，分别提供显示名称和解释，不改变配置模型中的值或默认值。

本表仅列配置接口；可选任务接口和执行边界见 [Web 部署指南](web-deployment.md)。不提供任意命令或维护 API。校验业务结果为 `{valid, result, errors}`；无效参数可能 HTTP 200 且 valid=false。格式/权限/存储错误为相应非 2xx 与 `{error:{code,message}}`；不依赖中文错误文本解析任务状态。接口拒绝未知请求字段、重复 JSON 键、非有限数值、错误类型及超长数据。

导出含密码时，服务仍只接受当前配置声明的凭据键（`harbor` 与 `node:<节点名>`），节点必须有 `password_env` 变量名；未知键或空变量名会被拒绝。导入路径继续拒绝任何密码变量赋值。

## 适用边界

Web 是控制端本机单用户工具，支持配置模式与显式启用的部署模式，不是远程多用户管理平台。配置导出和只读校验不替代真实 SSH/密码/sudo、主机信任、存储或集群验收。已有集群不得通过导入草稿、改名或改变状态目录来绕过原回执。

新修订的配置、草稿、受限导入及接入保护采用隔离回归验证；不能据此宣称接收方实机部署、HA、重启恢复或其它系统组合已通过。实际前置条件、已有实机范围与已知限制见 [部署前置条件与验收边界](deployment-checklist.md)。测试记录和历史现场材料由交付方单独保管，不作为用户手册附件。
