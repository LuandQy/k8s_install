使用说明与边界

    

      
三步向导

      
第 1 步直接编辑当前配置；第 2 步执行只读校验与计划；第 3 步直接提交后台部署任务。页面不保存草稿，持久化请导入/导出 .env；密码只保留在当前页面内存。

      
节点矩阵与数据盘预览

      
矩阵主行展示主机名、连接/内网 IP、连接方式、SSH 用户/端口、SSH 密码、Harbor 密码（仅勾选 Harbor 且为受管单机/HA 时显示）、角色和展开/克隆/删除。展开行显示 OS、架构、数据策略、设备和数据盘路径预览；数据策略为 native 时只声明数据根目录，不创建组件软链接、不格式化/分区；existing/auto/format 才显示 containerd、kubelet、docker、Harbor 的数据盘链接。etcd 始终保留在系统盘 /var/lib/etcd，不做软链接。启用本地存储或 NFS 时仍会创建 LOCAL_PATH/NFS_PATH（默认 /data/local-pv、/data/nfs），最终以 prepare/storage 检查为准。

      
表单与 env 预览

      
第 1 步可切换“表单编辑 / env 预览”。env 由服务端按当前表单生成，隐藏字段已剔除，不包含密码；它只用于核对，不授权执行，也不替代 CLI 加载。

      
Harbor 模式

      
仓库模式为单节点受管 Harbor、HA Harbor 或外部已有 Harbor。选择模式后高级区会展开：HA 额外要求 VIP/VRRP；外部模式不填写受管 Harbor 源目录，但仍需地址、域名和可信 CA；HTTP 模式隐藏 TLS 证书字段。HA Harbor 当前仅支持配置与只读计划，执行仍按 CLI 验收流程。

      
分阶段执行

      
第 3 步除全量安装外，可独立执行：前置检查（access→prepare→deps→services-init→services-verify）、Harbor（harbor-install→harbor-projects→images-import→images-verify）、K8s（k8s-install→node-images-verify→cluster-verify→ledger）。建议按 1→2→3 顺序；各按钮均直接提交后台任务，不弹二次确认。停止只在阶段边界生效，不回滚已完成操作。

      
默认值

      
默认拓扑为 3 控制平面 HA + kube-vip + 单 Harbor，NTP/NFS 默认由第一个控制平面提供。单机模板使用 local 连接和 All-in-One 角色。模板只是起点，IP、域名和密码必须按现场修改。

      
参数显隐

      
依赖模式、NTP/NFS、Harbor 启用和节点连接/认证会动态显隐；隐藏字段自动 disabled，提交前会移除，不会向后端提交无效的隐藏值。高级项默认折叠，修改后出现“已修改自定义项”。

      
密码与配置

      
Harbor 管理员密码内嵌在勾选 Harbor 角色的矩阵行，所有 Harbor 行共享同一个页面值；节点 SSH 密码按行独立。密码只存在于当前页面内存，刷新或关闭页面后需要重新填写，默认 .env 导出和配置对象不包含密码。sudo 提权仍要求预先配置免密，CLI 不采集 sudo 密码。

      
离线归档 SHA256

      
前端不再提供手动 SHA 输入/计算。后端在执行校验、预览和部署前，按归档路径读取同目录 .sha256，否则读取 artifact/SHA256SUMS。实际部署仍由 CLI 校验归档字节；外部路径请使用 CLI artifact-sha256 --file。

      
执行器

      
第 3 步需要管理员启动并已连接执行器。点击“一键开始安装”会校验配置、生成计划、提交 deploy.sh all，不显示二次确认弹窗；日志和台账来自执行器。日志不做脱敏，可能包含密码和私钥路径。

      
CLI 对齐

      
按钮和导出的 env 使用相同字段：DEPS_MODE、ARTIFACT_FILE/SHA256、NTP_*、NFS_*、COMPONENTS、SSH_AUTH_MODE。CLI 仍可用 ./deploy.sh cli --step <stage> 接管。

      
安全与故障

      
这不是多用户远程平台。已有集群、reset、扩容和故障恢复使用 CLI 原流程。执行失败时保留当前配置、任务、日志和台账，不要删除回执或重复提交。
